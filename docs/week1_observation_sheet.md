|---|---|
| **1. Problem and beneficiaries** | Problem: Students cannot get timely answers about courses, prerequisites, and graduation requirements.<br>Beneficiaries: Undergraduate students & academic advisors (reduced workload). |
| **2. AI stack layer most visible to user** | Application Development layer: The user sees a chat interface and receives answers.<br>The model layer (GPT-4o-mini) and infrastructure layer (ChromaDB, FastAPI) are invisible. |
| **3. Quality dimensions (at least 3)** | **Accuracy:** Does the system give correct course prerequisites?<br>**Measure:** Compare against official catalogue.<br>**Latency:** How fast does it respond?<br>**Measure:** Time from query to first response in seconds.<br>**Fairness:** Does it answer equally well for all faculties?<br>**Measure:** Accuracy compared across faculties. |
| **4. What did the system do WELL? Provide a specific example and evidence.** | When asked "What are the prerequisites for COMP301?", the system retrieved the correct answer from the course catalogue and cited the source page. **Response time:** 2.1 seconds. |
| **5. What did the system do POORLY? Provide a specific example and evidence.** | When asked about an Arts faculty course, the answer was less detailed, suggesting under-representation of Arts content in the data. This is a fairness risk. |
| **6. Responsible AI risks identified (Kleppmann & Riccomini, 2026, Ch. 14)** | **Risk 1 — Hallucination:** Model invents a course code not in the catalogue → student enrols incorrectly.<br>**Risk 2 — Fairness:** Arts students receive worse answers than Science students → unequal access.<br>**Risk 3 — Safety:** Distressed student asks for emotional support → system responds inappropriately. |
| **7. If you could fix ONE thing** | Add a guardrail that detects distress in student queries and redirects to the university counselling service, rather than attempting to help. |
